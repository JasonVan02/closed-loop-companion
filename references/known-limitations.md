# Known Limitations

- ChatGPT task API、类型、可用入口、缓存及返回格式可能变化；每次先探测，不能把某次联调的观察当永久标准。
- 读取与单条消息上限须以当前接口为准；完整消息16,000 UTF-16 units是保守默认，不是服务商保证。多包仍受会话总上下文和工具返回截断影响，逐包回读也不证明模型永久保留了全部上下文。
- 不保证所有账号、客户端和模型一致；当前 app tool 不公开具体 ChatGPT 模型时写 unknown，不能说一定用了最新模型。
- 工具可用不等于用户已授权材料传输。外部传输受系统审批与用户范围限制；拒绝时保存可恢复状态，不能绕过。
- 文本 send 不能证明图片已传给模型；图片通道需独立验证。真实审美和产品取舍需要 Human，视觉 Review PASS 不能代替用户验收。
- Review 不是形式化证明。结构校验器不能判断伪造日志、测试是否充分、设计是否好；原始 tool 记录与独立语义审查仍必需。
- 敏感检查是保守启发式，可能误报/漏报；需核查实际内容和授权，不是 DLP 产品，不接触真实凭据来测试。
- 本 Skill 是可执行指令与本地辅助工具，不是自运行守护服务。当前任务持续运行时可自动交接；任务停止后需后续用户/平台触发恢复。不承诺永久后台监控。
- 新建真实 ChatGPT session 受当前 create schema 与显式创建授权约束；无法访问真实 ChatGPT 时报告 LOCAL_REVIEW_ONLY，同时原 FULL Gate 保持 BLOCKED，不能以内部 Reviewer 代替后宣称通过。见 [capabilities](capabilities.md)。
- 多代理运行受平台槽位和权限限制；角色可以串行，独立性仍要保留。没有可用独立审查条件就不能自报内部独立 PASS。
